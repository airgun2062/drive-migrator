# Drive Migrator

Rust workspace: a cross-platform (Linux, macOS, Windows) tool that transfers folder trees between drives with resume and verification, and finds duplicates, near duplicates, and document versions. The full design is in `SPEC.md`. Read only the section relevant to the current task, not the whole file.

Current phase: P8 done, out of roadmap order (built before P7 - see SPEC.md section 11; P7's image tier and large-file/chunk-resume policy were not blockers for the GUI, since the GUI just renders whatever `engine` reports exist and gains new data sources as later phases add them). `crates/gui` (Tauri 2, Rust) plus `crates/gui-frontend` (React + TypeScript, Vite) implement the 5 screens from SPEC.md section 9: Scan, Resume and reconcile, Review, Version history, and Transfer progress, all wired to `engine` directly through Tauri commands (`crates/gui/src/commands.rs`) - no logic duplicated from the CLI. Lists use a hand-rolled windowed/virtualized component (no library) per section 9's "tens of thousands of rows" requirement. Transfer progress streams live via a new `engine::run_with_progress` (additive; `run` is unchanged and still what the CLI uses). Untested: no interactive click-through of the 5 screens against real fixtures yet (only confirmed the binary launches cleanly and stays up); macOS/Linux builds are unverified locally and rely on CI. Still open from P5, both blocked on human input rather than effort: T4 embeddings and the threshold calibration tool (~200 hand-labeled real pairs, kept outside the repo). Next: P7, perceptual image matching (required, must be crop-robust; algorithm choice deferred until evaluated against real test images) and the rest of P7 (large-file policy, protected classes, chunk resume, optional video tier). Update this line when a phase is finished.

## Hard rules

- Never modify or delete files in the source location. No code path may write to the source root.
- Never test against real user data. Use synthetic fixtures only, generated by `xtask/`.
- Every file copy: write to `<name>.part`, hash while writing, fsync, compare with the source hash, then atomic rename.
- Paths: use `Path` and `OsString`, never assume UTF-8. Use a helper for Windows long paths (`\\?\` prefix). Normalize (NFC, case-fold) only for comparison and keep the raw path for writing.
- No `unwrap()` or `expect()` in library code that touches the filesystem. Return typed errors (`thiserror`).
- Stream files with fixed buffers. Never load a whole file into memory.
- Filesystem timestamps never define a duplicate. They only break ties.
- No GPL dependencies (for example Slint). Check a crate's license and maintenance before adding it, and ask before adding any dependency.
- Do not change a design decision silently. If SPEC.md needs to change, propose the change and update SPEC.md.

## Commands

```
cargo fmt --all
cargo clippy --all-targets -- -D warnings
cargo test --all
```

All three must pass before a commit, and CI must pass on ubuntu, macos, and windows.

## Workflow

- Work on one roadmap phase at a time. Start a fresh session per phase.
- Plan briefly, implement, run the tests, then commit with a clear message.
- Keep context small: do not paste large outputs, and use head or tail on long test output.
- The developer is on a Pro plan, so avoid re-reading files unnecessarily and avoid exploratory rewrites.
- After each phase, summarize what works, what is untested (especially on Windows and macOS), and what the next phase needs.
